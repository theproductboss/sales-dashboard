The one idea to teach

Everything in this training hangs on one sentence. Say it early, draw it, and come back to it in segment 4.

Your database doesn't know how to rate a sales call. Neither does your automation. An AI step only knows what you send it on that run. The rubric has to travel with every transcript.

There are three separate jobs, and people blur them together. Show this table in segment 4:

JobWhat it doesExamples
The brainKnows how to judge a call: the rubric, the rules, the feedback formatThe skill (for chatting with Claude); the automation prompt (for unattended runs)
The plumbingMoves the recording and transcript from place to place and calls the AIZapier, Make, n8n, a script
The memoryStores each call, its score and its review, so you can sort, filter and spot patternsHere: a Notion board holds each call's record and review, and a Claude dashboard, kept in sync through a service on Render, is what the team actually reads. Elsewhere: Airtable, a spreadsheet, a CRM

The highlighted box is the only place judgment happens. Everything else just moves files.

1 · Start with the end

Show the finished result first, so every later step has a reason.

On screen
The demo Closer Tracker, Call Reviews tab: the score-by-call chart, then one review card with what went well and what to work on.
Say
"Every call my team takes lands here, scored and coached, right next to our booking and close numbers. Nobody typed this. (Names are changed for today.) In 30 minutes you'll know how to build it, and the one piece most people get wrong."
Do
Point at one review card: what went well, what to work on. Then switch to the Closer Dashboard tab to show the scores sit beside show rate and close rate.
0:03–0:13

2 · Build the brain

Learners see the three moves that turn expert know-how into a skill: steal a structure, use real transcripts, make it gradable.

On screen
SKILL.md for 3 minutes, then references/scorecard.md for the rest.
Teach
  1. Copy a structure that already works. I took apart good skills first. Each has a short main file (when to use it, a few rules it never breaks, the steps, the output format, the failure modes) and the depth in reference files.
  2. Feed it full transcripts, not summaries. Web summaries of Hormozi, Miner, Shelby Sapp and Dan Martell were thin. The skill got good when I pasted in full video transcripts. Every idea is tagged as word-for-word or paraphrased, so the AI never makes up a quote.
  3. Make it gradable. Ten areas, weighted to 100, with a written description of a 1, a 3 and a 5 for each. Plus automatic flags like "never asked for the sale" that a high score can't hide.
Say
"Two rules do most of the work. No quote from the call, no score. And the objection at minute 42 was usually caused at minute 8, so the feedback fixes minute 8."
Watch for
Writing a skill as one giant prompt. Keep the main file short; depth goes in the reference files.
0:13–0:16

3 · Prove it works

Show that you test on calls you already understand before automating anything.

On screen
The chat with one test call already reviewed. Don't run a review live; it takes too long.
Say
"I ran three calls I knew cold: a clean close, a clear loss and a messy follow-up. If it can't rank those the way I would, automating it just spreads the mistake faster."
Check
The clean close scores 85+, the ranking matches your gut, and every quote is actually in the transcript.
0:16–0:26

4 · Wire the pipeline

Learners understand all three automations, and above all how the database "knows" how to rate a call.

On screen
The diagram and the three-jobs table at the top of this page, then the automation editor. Keep the database open in another tab.
Teach

Zap A: new recording → save to Drive → create the row. Status: Waiting on transcript.

Zap B: new transcript → save to Drive → find the row by meeting ID → add the link. Status: Ready for review.

Zap C, the review: status becomes Ready for review → get the transcript's text → send it to the AI with the review prompt → read the JSON → write the score, grade, outcome, flags, top fix and drill into the row → set status to Reviewed last.

Say
"Here's the part nobody explains. The skill lives in the chat app. An automation doesn't load skills. When Zap C calls the AI, it knows nothing except what we send on that run. So the rubric goes in the prompt, every time. That's this file: the skill squeezed into one prompt, with answers a machine can file."
Do
Open automation/notion-review-prompt.md and point at its three parts: the rubric, the message with the transcript, and the JSON that comes back. Show that the outcome choices match the database's options exactly.
Watch for
Sending the transcript link instead of its text, asking for prose instead of JSON, and marking a row Reviewed before the writes succeed.
0:26–0:30

5 · Keep it improving

The system gets better every week instead of drifting.

Teach
  • Corrections become house rules. "We do that on purpose" gets added, dated, to the prompt.
  • Version the prompt. Each review records which rubric version scored it.
  • Outcomes beat scores. After 20 calls, check that high scores actually close, and adjust the weights if not.
On screen
The demo dashboard: filter Call Reviews by one closer to show their average and best score over time.
Close with
"Your homework: get three full transcripts from experts you trust, write what a 1, 3 and 5 look like for the three things that matter most on your calls, and test on three calls you know before you automate anything."

Reference: the review step

Not presented in the 30 minutes. Keep it on hand for questions.

Recommended start

Automation calls the AI

Zap C sends the review prompt and the transcript to the model and writes the JSON back.

  • Runs on every call within minutes, with no one involved
  • Structured fields every time, so sorting and filtering just work
  • You maintain a condensed prompt alongside the full skill
  • Costs one AI call per sales call
Highest quality

An AI agent on a schedule

An AI assistant with the full skill installed and database access runs daily: "Review every row marked Ready for review."

  • Uses the complete skill, including rep patterns and saved examples
  • Can compare against earlier calls from the same rep
  • Batch, not instant; depends on the agent having access to the database and transcripts
  • Needs a strict output template, or the format drifts between calls

The user message Zap C sends

Call name: {{Call name}}
Rep: {{Rep}}
Call date: {{Call date}}
Length (min): {{Length}}

Allowed outcome values (choose exactly one):
Closed – Collective | Closed – Sales Accelerator | Closed – Inner Circle | Follow-up | No decision | Not a fit

Allowed revenue band values (choose one, or null):
$25K–$50K | $50K–$250K | $250K–$1M | $1M+

TRANSCRIPT:
{{full transcript text}}

Swap the outcome and revenue band lists for your own database's options. The full system prompt, JSON format and field mapping are in automation/notion-review-prompt.md.

Troubleshooting

SymptomLikely causeFix
Reviews use a different scorecard each timeThe AI step has no rubric, or a vague onePaste the full system prompt into the AI step
Score is in the page text but the number field is emptyThe output is prose, not JSON, so nothing maps to the fieldRequire JSON output, add a parse step, map each field
Outcome select is blank, or gets a new odd optionThe model's wording doesn't exactly match the select optionsList the exact allowed values in the user message
Rows stuck on "Ready for review"Zap C errored before the last stepCheck the automation's run history; status should change only after the writes succeed
